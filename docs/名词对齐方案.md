# 名词对齐方案 · 从「会做」到「会说」

> 解决的问题：**掌握的知识和市场名词对不上**——做过的不知道叫什么，听过的又没做过，一开口就乱。
> 配套：`能力对账表.md`（名词对照清单）、`面试讲述手册-可讲点与话术.md`（怎么讲）。
> 生成日期：2026-09-18

---

## 一、先定性：三种"对不上"，解法完全不同

你之前把这三件事混成了一件事，所以觉得"哪都不行"。拆开看，性质差很远：

| 类型 | 症状 | 你的情况 | 解法 | 代价 |
|---|---|---|---|---|
| **① 有实无名** | 做过，但不知道它叫什么 | **大部分**（对账表 35 条） | 名词卡 | 今天，2 小时 |
| **② 有名无实** | 听过名词，但没做过 | **少数**（C 档 6 项） | 补课清单 | 两周，穿插 |
| **③ 名实都有，说不出口** | 知道，但开口就乱 | 少数 | 复述练习 | 每天 10 分钟 |

**关键判断**：你最大的问题**不是 ②**（你只缺 6 项，而且其中 3 项是时间问题）。你真正的问题是 **① 和 ③**。

而 ① 是所有类型里**最便宜**的一类——**学费你已经付过了，只是没开发票**。

## 二、总纲：三层对齐

```
                    ┌─────────────────────────────────┐
   L1  存量对齐      │ 把「做过的事」挂上名词           │  今天 · 2 小时
      （最便宜）     │ 工具：能力对账表 → 名词卡         │
                    └─────────────────────────────────┘
                                    ↓
                    ┌─────────────────────────────────┐
   L2  数字对齐      │ 把「我觉得」换成「实测 X%」       │  本周 · 半天
      （最值钱）     │ 工具：15 道黄金题 + A/B 对照      │
                    └─────────────────────────────────┘
                                    ↓
                    ┌─────────────────────────────────┐
   L3  框架对齐      │ 把「手写过」变成「用过」          │  两周 · 半天
      （最省力）     │ 工具：LangGraph 重写 + 对照笔记   │
                    └─────────────────────────────────┘

   穿插进行：工程化底盘（Docker / Linux / Python）—— 简历门槛，不必等前三步
```

顺序不能反：**先 L1**，因为 L1 让你立刻停止"自我降级"；**再 L2**，因为数字能把 L1 的十项全部点亮；**L3 最轻**，因为你知道原理，只是换 API。

## 三、L1 · 存量对齐：把对账表变成「名词卡」

### 名词卡的格式（就这四个字段）

```
┌────────────────────────────────────────────────────┐
│ 名词：混合检索 Hybrid Retrieval                     │
├────────────────────────────────────────────────────┤
│ 一句话：向量召回 + 关键词召回两路并行，再按排名融合   │
├────────────────────────────────────────────────────┤
│ 我项目里的位置：lib/knowledge.ts  retrieve() 371-383│
├────────────────────────────────────────────────────┤
│ 我可以说的一句话：知识库用混合检索，因为纯向量会把    │
│   「张三」这种专名稀释掉，关键词那一路专门兜这个      │
└────────────────────────────────────────────────────┘
```

**为什么必须手写，不能只看表**

| 只看对账表 | 手写名词卡 |
|---|---|
| 认得出名词 | 说得出位置 |
| 记住"有这回事" | 记住"我做过这回事" |
| 被追问就沉默 | 被追问就报行号 |

第 3 栏（位置）是**证据**，第 4 栏（一句话）是**答案**。这两栏才是面试真正要的。

### L1 执行步骤（30 分钟一轮，共 3 轮）

**第一轮（30 分钟）· 检索篇**
1. 打开 `docs/能力对账表.md` 的「① 检索」表格
2. 打开 `lib/knowledge.ts`，**边读代码边写卡**——不要只看表，看表记不住
3. 8 条各写一张卡
4. 收尾自测：合上文件，随机抽 3 个名词，看能不能说出"在哪 + 一句话"

**第二轮（30 分钟）· 编排篇**
1. `lib/collection-workflow.ts` 是注释写得最全的文件，从它开始
2. 8 条各写一张卡
3. 重点写「人机卡点」「条件边」「异常分层」这三张——它们是面试差异化最大的

**第三轮（30 分钟）· 工程底座 + 工具篇**
1. `lib/api.ts` / `lib/tool.ts` / `app/api/login` / `app/api/me` / `mcp-server/src/server.ts`
2. 这几块你最容易"觉得没什么好讲的"，恰恰相反——**多端凭证适配、错误归一化、表驱动接口**这三条最能证明工程能力

**第四轮（30 分钟）· 反查漏**
回到对账表，把 35 条全部盖住，只看左列（"你实际写的"），看能不能反推出右列的名词。**能反推出来的，才算真对齐了。**

### L1 自测题（答不上就回去补卡）

| 抽到的名词 | 你应该能立刻说出 |
|---|---|
| 混合检索 | 两路召回 + RRF 融合，在 `retrieve()` |
| RRF | 用**排名**不用分数，因为两路尺度不同 |
| 交叉编码器重排 | 只跑 top-20，因为成本是 O(n) |
| 优雅降级 | `rerankChunks` 三处 `return candidates` |
| 条件边 | `edges` 的 Map 值**可以是函数** |
| 状态补丁 | 节点返回 Partial，引擎 `Object.assign` |
| 人机卡点 | `humanApprove` 只贴 `needsApproval`，不阻塞 |
| 确定性护栏 | 发送是不可逆动作，永远不进图 |
| 异常分层 | `loadDebt` 故意没 catch，异常穿到最外层 |
| 适配器 / 防腐层 | 两跳取数 + 算账龄，落在 `loadDebt` 一个节点 |
| 错误归一化 | 超时/断网/HTTP 错误全转中文，因为要进 AI 上下文 |
| 多端凭证适配 | 浏览器 cookie，小程序自定义头 |

## 四、L2 · 数字对齐（你唯一的结构性缺口）

### 为什么这一步排第二

1. 你**所有**的优化现在都是"我觉得更准"，没有一个数字；
2. 面试三大翻车点里有一条就是"**chunk 重叠率与召回率的平衡**"——你答不上不是因为不懂，是因为**没量过**；
3. 跑完这一步，对账表 A 档那十项会全部从「我做了」升级成「实测提升 X%」。

**这一步的性价比是全表最高的**：代码你几乎都写好了，只差造题、跑一遍、数一下。

### 执行步骤

**Step 1 · 造题（约 20 分钟）**
从 `knowledge-base/` 的三份 md 出 15 道题，覆盖四类：

| 类型 | 题量 | 例 |
|---|---|---|
| 事实查询 | 5 | "退货几天内可以申请？" |
| 多条件 | 4 | "A 级客户的账期和信用额度分别是多少？" |
| 专名 / 精确词 | 3 | 含具体客户名、单号、制度名称的题 |
| 不该命中 | 3 | 问知识库里完全没有的话题（看会不会硬凑） |

每题标注**正确答案在哪份文档**（source）。

**Step 2 · 写评测脚本**
逻辑很朴素：读题 → 调 `retrieve(question, { topK: 3 })` → 看 top-3 里有没有正确的 source → 打勾。
一个约 40 行的脚本，放 `scripts/eval-rag.ts`，跑法：

```bash
node --env-file=.env node_modules/tsx/dist/cli.mjs scripts/eval-rag.ts
```

**Step 3 · 跑基线（纯向量）**
`lib/knowledge.ts` 第 **364~369 行** 那段注释保留的纯向量代码，就是基线。
把 `retrieve()` 里的混合部分临时换成它，跑一遍，记下分数。

**Step 4 · 跑现行（混合 + 精排）**
切回来，再跑一遍，记下分数。

**Step 5 · 收口成一句话**

> "裸向量召回 9/15，混合 + 精排之后 13/15，主要收益来自专名检索——纯向量会把'张三'这种词稀释掉。"

**（数字是示例格式，实际以你跑出来的为准。）**

### 顺带把第二件事做掉：chunk 参数对照

现在切片大小是写死的。做 2~3 组参数（如 300 / 500 / 800 字，overlap 0% / 20%）跑同一套题，就能正面回答"chunk 怎么定"了——**这就是翻车点第二条的标准答案**。

## 五、L3 · 框架对齐（把"手写过"变成"用过"）

你已经手写过引擎，所以这一步的本质是**换名字，不是学新东西**。别人学 LangGraph 要理解"什么是状态图"，你只需要对照"它这个 API 对应我哪三行"。

### 两条路

| 路线 | 内容 | 代价 | 收益 |
|---|---|---|---|
| **A · 顺手路**（建议先走） | `@langchain/langgraph`（TS 版）重写 `collection-workflow.ts` | **半天** | 简历能写 LangGraph，且能讲清它和自己引擎的差异 |
| B · 门槛路 | Python + LangGraph + FastAPI | 1~2 周 | 顺手补上 JD 硬门槛 Python / FastAPI |

**建议先 A。** 因为 A 能立刻产出一个"**对照实验**"——「我的 45 行 vs 框架」这个素材在面试里极好讲。
B 放到工程化底盘阶段，和 Docker / Linux 一起补。

### L3 执行步骤（路线 A）

1. 装依赖：`@langchain/langgraph`
2. 把 4 个节点函数**原样搬过去**——你现在的签名已经是 `(state) => Promise<Partial>`，几乎不用改
3. 用 `StateGraph` 声明状态结构，`addNode` 注册节点
4. 条件边用 `addConditionalEdges('classify', ...)`，对照你自己的 `edges.set('classify', fn)`
5. 跑同一批客户（李四 / 张三 / 王五 / 赵六），对比输出是否完全一致
6. **写对照笔记（这才是真正产出）**，固定问三个问题：
   - 框架替我做了什么，是我手写版没做的？（大概率：持久化、中断恢复、可视化）
   - 我手写版有什么是框架不提供的？（大概率：零依赖、完全可控、40 行读完）
   - 如果重来，我会不会一开始就用框架？为什么？

第 6 步的笔记，直接就是面试答案。而且**你有资格回答这个问题**——很多人只会用框架，回答不了"框架到底替你做了什么"。

## 七、什么算「对齐了」（三个可验证的标准）

1. **抽词能定位** —— 随便抽一个名词，3 秒内能说出"我项目里在哪一行附近"；
2. **讲述无降级** —— 讲 RAG 时不再出现"只是""简单地"这类词（写下来念一遍，自己听）；
3. **缺口变方案** —— 被问到没做过的（评测 / 持久化）时，能给出具体方案而不是只说"没做"。

达到这三条，你的自述能力和实际能力就同步了——**"感觉自己啥都不会"这个症状会自动消失**，因为它本来就是信息失真造成的。
